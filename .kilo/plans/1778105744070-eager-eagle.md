# Plan: Display File/Folder Size and Sort by Size

## Current State Analysis

The codebase already has partial implementation:

1. **Size sorting exists** (`state.rs`):
   - `SortOrder::Size` enum variant
   - Sorting logic in `sort_entries()` - directories first, then by size descending
   - Accessible via `Ctrl+O` (cycle sort)

2. **Size display exists** (`state.rs` - `FileEntry::size_formatted()`):
   - Files: shows human-readable size (B/K/M/G)
   - Directories: always shows `"<DIR>"` placeholder
   - Directory actual size is stored but not displayed

3. **Directory size calculation** (`fs.rs` - `get_dir_size()`):
   - Recursive calculation exists
   - Controlled by `calculate_dir_size` flag (persisted in config)
   - Toggle via `Ctrl+I` (`MenuAction::ToggleDirSize`)
   - When disabled, directory size = metadata size (typically 4K), not contents

## Proposed Improvements

### 1. Show Actual Directory Sizes in Display
**Problem**: Directories always show `"<DIR>"` even when size is calculated.

**Solution**: Modify `size_formatted()` in `state.rs`:
- When `is_dir` is true:
  - If size > 0 (calculated), show formatted size (like files)
  - Optionally add indicator like `"/"` or `"<DIR>"` suffix to distinguish
  - If size == 0 (not calculated or empty), show `"<DIR>"` or `"0B "`

**Alternative**: Always show calculated size for directories, no placeholder needed since directories have size.

### 2. Add Direct "Sort by Size" Action
**Problem**: Only cycle sort exists (`Ctrl+O`). Users want direct sorting.

**Solution**:
- Add `MenuAction::SortBySize` variant in `menu.rs`
- Add keybinding `Ctrl+S` (or alternative if conflict) in `main.rs`
- Implement `sort_by_size()` method in `AppState` that sets `sort_order = SortOrder::Size` and calls `sort_entries()`
- Add command palette entry for "Sort by Size"
- Update menu to include separate "Sort by Size", "Sort by Name", "Sort by Date" items (replace or supplement CycleSort)

### 3. Show Sort Direction Indicator
**Problem**: Status bar shows "Sort: SIZE" but no direction (asc/desc).

**Solution**:
- Change sort order to enum with direction: `SortOrder::NameAsc`, `NameDesc`, `SizeAsc`, `SizeDesc`, etc.
- OR add `reverse` boolean field to `AppState`
- Update `sort_entries()` to respect direction
- Update status bar to show e.g., `"Sort: Size ↓"` or `"Sort: Name ↑"`
- Add keybinding to reverse sort direction (maybe `Ctrl+R` in view mode, or `R` when sorted)

**Simpler approach**: Keep current direction (descending for size/date, ascending for name) as defaults, add `reverse_sort` flag.

### 4. Persist Sort Order in Config
**Problem**: Sort order resets on restart.

**Solution**:
- Add `sort_order` field to `Config` struct
- Save/load from config file
- Initialize `AppState` with saved sort order

### 5. Improve Size Column Formatting in UI
**Problem**: Size column width fixed, may truncate large sizes or misalign.

**Solution**:
- Ensure consistent column width (currently using `{:>8}` format in main.rs:1258)
- Largest expected size: `999.9G` = 7 chars, `8` width is sufficient
- No change needed unless we add direction arrows

## Implementation Order

1. **Fix directory size display** - Show actual calculated sizes
2. **Add direct sort actions** - Separate MenuActions for Name/Size/Date
3. **Add sort direction indicator** - Visual feedback in status bar
4. **Persist sort order** - Save/restore from config
5. **Update keybindings** - Ensure no conflicts, document changes
